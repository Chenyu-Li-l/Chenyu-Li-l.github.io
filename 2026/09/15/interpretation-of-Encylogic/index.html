interpretation of Encylogic

ICCAD’26 论文 | EncyLogic：把逻辑综合变成”序列生成”

SUMMARIZE：EncyLogic 发现逻辑综合中大量存在”中间变坏、终值反超”的天使序列（angel sequence），据此把综合问题从”逐步动作选择”重构为”序列分布学习”——先用物理验证过的天使序列预训练一个 Transformer（SeqFormer），再用布线后真实时延作奖励的 GRPO 式强化微调对齐物理实现，最后用带物理先验的领域定制 MCTS（SeqTree）在线适配每个新设计。在完全未见过的设计上：布线后面积-时延积（ADP）比 BOiLS 低 **17.6%**，工艺映射时延比 &deepsyn 低 **24%**，FPGA LUT 数低 **21%**。

论文：EncyLogic: Logic Synthesis as Sequence Generation with Learned Priors and Physical Alignment（ICCAD’26，2026 年 11 月 8–12 日，San Jose）。本文所有数字均出自论文正文、Table 1–3 与 Fig. 1–6；标注”个人解读”的部分是博主观点。

0. TIPS:

  • 逻辑综合（logic synthesis）：把 RTL/布尔逻辑变成工艺库门电路的编译过程。业界常用 AIG（And-Inverter Graph） 做中间表示——每个节点是一个 2 输入 AND 门，边上可以带反相。开源工具 ABC 提供了一整套优化原语：balance（压深度）、rewrite / refactor（局部重写减少节点）、resub（重结构化）等。
  • 优化序列：一串操作组成的”菜谱”，例如 b → rw → rf → rs。操作数为 k、长度为 L 的序列空间是 k^L，指数爆炸，穷举不可行。
  • 前端 vs 后端：综合阶段（前端）看的是 AIG 节点数、逻辑级数这类结构性代理指标（proxy）；布局布线（后端）之后才见真章——时延、面积、拥塞。代理指标好 ≠ 物理指标好，这就是著名的”前后端鸿沟”。
  • 时代背景：先进工艺节点 + 迭代式再综合（iterative re-synthesis）流程，使优化目标从可解释的 PPA（Power/Performance/Area）指标滑向黑盒代价函数——2024 年 ICCAD CAD Contest Problem A 正式化了这一工业趋势。指数空间 × 不可微、不可解释的目标，让一切依赖代理信号做剪枝的传统方法失去指南针。

带着这四个概念，我们开始提问。

Part 1 · 问题定位：这篇论文到底在攻什么？

Q1：这篇论文要解决的核心问题是什么？

三层递进：

  1. 空间指数大：候选优化序列的数量随长度指数增长，穷举不可行；
  2. 目标不透明：优化目标从可解释的结构指标演变为一般的、往往是黑盒的代价函数——没有梯度、没有可解释信号；
  3. 现有方法集体依赖前端代理做逐步引导：代理一失效就”失明”，而且贪心策略会拒绝任何让代理指标暂时恶化的步骤，从而锁死在局部最优。

论文的核心论断是：这不是”更聪明的逐步动作选择”能解决的问题。**问题的正确抽象是”学习好序列的分布”**——即把逻辑综合从 RL 式的 MDP 决策，重新表述为生成模型式的分布学习。

Q2：什么是 angel sequence（天使序列）？名字从哪来？

定义：在完整执行一段优化序列的过程中，前端结构性指标（如 AIG 节点数）先暂时恶化、最终却落到比贪心搜索更优的代价的非单调轨迹。

论文的动机实验（Fig. 1）很有说服力：在 10,000 条 500 步的随机序列中，始终存在一小撮这样的非单调轨迹；其中最好的天使序列在 AND 节点缩减上比在线搜索基线 AlphaSyn（ICCAD’23）**好约 10%**，而且到 500 步仍未收敛、还在持续改进。这说明长 horizon 的优化油水很足，只是没人捞得到。

名字借自 Yu 等人（ICCAD’18）提出的 angel/devil flow 区分：带来好 QoR 的综合流程是”天使”，坏的是”魔鬼”。

一个直观类比：登山时想上更高的峰，往往必须先下到谷底再从另一侧爬——贪心算法永远不肯下山，所以永远看不见谷对岸更高的山。天使序列就是”肯下山”的路线。

Q3：既然随机采样都能撞见天使序列，为什么现有方法抓不住？

论文把现有方法分成四类，逐一”验伤”：

方法流派 代表工作 失效方式
在线强化学习 DRiLLS、FlowTune、AlphaSyn、RL-guided 探索等 用即时代理改进当 reward，逐步贪心，任何”暂时变差”的动作都会被拒绝
离线检索 ReLS、PIRLLS、Retrieval-guided RL 从静态数据集取序列，无在线适配，换设计就失灵
贝叶斯优化 BOiLS 长 horizon 下高斯代理 scaling 差，代价函数黑盒化后更是不可用
学习式代理/连续建模 DAC’25 扩散模型 仍以可解释的前端代理为中介，黑盒目标下引导信号消失

四类的共性：step-level 的代理引导。天使序列恰恰以”步级指标恶化”为特征，等于被所有代理引导方法结构性排除。当目标函数本身黑盒化，这最后一层引导信号也消失了。

Q4：”分布学习”和”动作选择”的区别是本质的吗？NLP/AlphaGo 类比贴不贴？

论文给出的类比有两层，都值得推敲：

GPT 类比：天使序列在组合空间中稀少、但结构连贯——恰似天文数字的 token 空间中”流利的句子”。学分布，就是学”哪些操作组合模式在物理上是有效的”，然后高效采样自高概率区域、剪掉其余。类比大体成立，但有一个不同：自然语言的”好”没有客观裁判，而逻辑序列的”好”最终可以由布线工具判死活。

AlphaGo/AlphaZero 类比：AlphaSyn 像 AlphaZero——纯自博弈，每个新设计都要重训策略网络，运行时开销巨大；EncyLogic 像 AlphaGo——先在”专家棋谱”（= 物理验证过的天使序列）上预训练策略，再在线搜索。这个类比非常贴切，但要注意：围棋有廉价且完美的终局胜负判定，而逻辑综合的”终局奖励”要跑完整布局布线才能拿到——贵得多。这一差异正是论文必须对 MCTS 动大手术（SeqTree）的根本原因，见 Q9。

Part 2 · 方法深挖：三个组件各干了什么？

Q5：EncyLogic 的整体架构是什么？

名字来自 Encyclopedia（序列百科全书）+ Logic。框架 = 一次离线训练 + 每设计在线搜索，共三大件：

组件 角色 对应的经典类比 关键机制
Sequence Encyclopedia 训练语料 语料库 / “专家棋谱” 两阶段蒸馏
SeqFormer（监督） 生成先验 GPT 预训练 操作序列与物理指标交错输入
GRPO 式 RL 微调（论文在消融中称 RLVR） 与真实代价对齐 RLHF / RL with Verifiable Rewards 组相对优势 + KL 罚
SeqTree 设计级在线适配 AlphaGo 的 MCTS PUCT 先验 / 虚拟损失 / 单调接受

Q6：训练用的”序列百科全书”是怎么蒸馏出来的？为什么要两阶段？

两阶段的动机是成本控制：布线评估很贵，不能对 396 万条随机序列全跑。

  • Stage 1（前端预筛）：33 个 AIG × 8 变体 = 264 个起点；每个起点均匀采样 15,000 条 25 步随机序列，按前端 QoR 取每变体 top-100，得到 23,500 条候选（理论 26,400，因算力截断）。此阶段只跑便宜的前端综合。
  • Stage 2（后端物理验证）：只对这 2.35 万条跑 OpenROAD 布线，按可验证的物理 reward（布线后数据到达时间） 取每 AIG top-50，最终得到 11,750 条物理验证过的天使序列。

这里有一个容易混淆的点值得澄清：天使序列的”恶化”是路径中段的属性，其最终前端指标依然是好的——所以 Stage 1 按”最终前端 QoR”筛选并不会天然把天使序列筛掉。Stage 2 的作用是再按物理真值重排，把”前端好看但布线难看”的假阳性挤出去。这正是对”前后端鸿沟”的正面回应。

Q7：SeqFormer 是什么？为什么要给模型喂时延/WNS 历史？

架构：decoder-only Transformer，6 层、8 个注意力头、隐藏维 512——一个”玩具尺寸”的语言模型。词表是 32 个组合式优化操作（由 dch/dch -f（2）× if -a -K n, n∈{3..6}（4）× mfs -e -W 20 -L 20 及 ±fx/st（2）× dc2/compress2rs（2）组合而成，2×4×2×2=32），外加 <bos> 等特殊符。图中示意用的 b / rw / rf / rs 是经典 ABC 操作的缩写，属示意记号。

最关键的设计：输入不只是操作序列，还逐前缀交错喂入物理指标轨迹——每条序列 ⟨<bos>, x₁, …, xₙ⟩ 携带对应的布线后数据到达时间 ⟨d₀, d₁, …, dₙ⟩ 与最差负裕量 WNS ⟨w₀, w₁, …, wₙ⟩。训练目标是交叉熵拟合天使序列的下一个操作。

直觉上，这像给模型一本”带绩效附注的操作日志”：模型从第一个梯度步起就把”操作 ↔ 物理后果”的关联刻进表示里，而不是先学语法、再补物理课。论文称这让 SeqFormer 习得”逻辑操作如何与最终物理实现质量相关”的潜层理解。

Q8：RL 微调为什么用 GRPO 式的组相对优势？这和 LLM 的 RLVR 是什么关系？

监督预训练只能学到”天使序列长什么样”，还不能保证生成序列对真实布线代价最优。于是第二阶段引入论文称之为”物理驱动的强化微调”（消融表中的 RLVR）：

对给定 AIG 设计，模型自回归采样 G 条轨迹；对每条序列 i 跑完整布局布线，测得真实布线后时延 D_i；奖励直接定义为：

$$r_i = -D_i$$

然后做组内标准化得到优势（无 critic、无 value 网络）：

$$A_i = \frac{r_i - \mu_r}{\sigma_r + \epsilon}$$

优化目标带对冻结参考模型 π_ref 的精确 KL 罚（k3 型无偏估计）：

$$\mathcal{L}(\theta) = \frac{1}{G\cdot T}\sum_{i=1}^{G}\sum_{t=1}^{T}\Big(-\log \pi_\theta(a_{i,t}\mid s_{i,t})\cdot A_i + \beta,\mathbb{D}_{KL}\Big)$$

三个设计选择的理由：

  1. 奖励可验证且不可伪造：D_i 来自 OpenSTA 的 signoff 报告，不是代理——这正是 LLM 圈 “RL with Verifiable Rewards” 的配方（个人解读：DeepSeek-R1 式的 GRPO 后训练流水线被完整平移进了 EDA）；
  2. 组相对优势替代 value 网络：同设计同组内比相对好坏，天然消除设计间基线差异，结构简单、训练稳定；
  3. KL 罚防止策略崩塌：把策略锚在物理验证过的天使序列先验附近，避免微调把预训练分布打散。

论文还强调框架是 reward-agnostic 的：r_i 可以换成任意后端指标或其耦合形式，时延只是代表性示例。

Q9：SeqTree 和标准 MCTS / AlphaSyn 到底差在哪？

标准 MCTS 的隐含前提是节点评估必须廉价（围棋终局判定瞬间完成）。而在”布线在环”范式下，每个叶节点都跑物理设计是不可承受的。SeqTree 的答案是把序列探索与物理评估解耦：

  • 选择/扩展（PUCT）：动作选择用 AlphaZero 式 PUCT，先验 P(s,a) 来自 GRPO 微调后的 SeqFormer：

$$UCT(s,a) = Q(s,a) + c_{puct}\cdot P(s,a)\cdot\frac{\sqrt{N(s)}}{1+N(s,a)}$$

论文自己坦言：因为逐步物理评估不可行，树内遍历实质上是”概率引导的 beam search“，主要由先验 P 驱动。节点首次访问时向 SeqFormer 查询分布并缓存。

  • 物理评估只在批级发生：每轮内层循环 b 条并行搜索各自走到深度 d，产生的 b 条候选批量异步送 OpenROAD 布线（Algorithm 1 行 10），奖励 R_k 回传更新 Q。评估次数从 O(节点数) 降到 O(轮数×b)。
  • 与 AlphaSyn 的本质差异：AlphaSyn 纯在线、每个新设计重训策略（AlphaZero 式自博弈的代价）；SeqTree 的策略是一次离线预训练 + 微调（AlphaGo 式），先验直接进 PUCT，在线只做搜索适配。

一个细节值得指出（细读者会注意到）：论文 §3.3.2 说树内回传”只增加访问计数 N 而非昂贵的物理奖励”，而 Algorithm 1 行 13 又写了 Backpropagate(R_k)。两者并不矛盾但表述有张力——合理的调和是：批内的多样性靠访问计数与虚拟损失维持（计数回传平滑惩罚高频分支），批后的物理奖励再更新 Q 供下一轮选择使用。复现时建议以 Algorithm 1 为准。

Q10：PUCT、虚拟损失、Dirichlet 噪声、单调接受……每个机制都在解决什么问题？

一张”问题 → 机制”对照表：

机制 解决的问题
PUCT（先验加权探索项 √N(s)/(1+N(s,a))） 在”相信先验”与”留探索余地”之间平衡；先验质量高时探索被有效压缩
虚拟损失（virtual loss） b 条并行搜索互不撞车——一条路径被占时临时降权，其他搜索走别的路
根节点 Dirichlet 噪声 防止所有轮次都挤进先验最高的同一分支，过早收敛（AlphaZero 同款技巧）
计数回传 廉价地平滑惩罚高频分支，保证 b 条候选高度多样
批量异步布线评估 把物理评估摊到批级，规避节点级评估的算力灾难
单调接受（D_best < D* 才更新） 硬保证：最终输出的序列在真实物理指标上绝不会差于起点——黑盒搜索的安全底线

最后一条常被忽视但极其重要：黑盒搜索方法最怕”探索半天反而交出更差的答案”，单调接受让 EncyLogic 的最坏情况被钉死在基线，这是它敢在工业流里用的底气。

Part 3 · 实验与结果：数字应该怎么读？

Q11：实验设置如何保证公平与泛化？

论文在这几点上做得相当规范：

  1. 完全未见的设计：所有测试 AIG 与训练集严格分离，以验证学到的”轨迹分布”而非记忆；
  2. 统一物理流水线：ORFS（OpenROAD-flow-scripts）+ ASAP7 预测型 7nm FinFET 库（7.5-track、RVT、Best-Case corner/0.77V/25°C、NLDM）；前端固定 Yosys + ABC；后端完整跑 floorplan → 全局/详细布局 → CTS → 全局/详细布线 → 寄生提取；
  3. 指标取自 signoff 报告：所有面积与时延直接从 OpenSTA 最终签核报告提取，不做任何估计；
  4. 可比算力下的四类基线：DAC’25（扩散模型/连续建模）、BOiLS（贝叶斯优化/黑盒搜索）、AlphaSyn（在线 MCTS）、&deepsyn（Berkeley ABC 的激进启发式，作传统方法”天花板”）；
  5. 硬件与工具：Intel Xeon + NVIDIA A800，PyTorch 出序列，OpenROAD 出真值。

注意两个读表细节：Table 2 的 ASIC 结果在 FF corner 评估（与 Table 1 的 Best-Case corner 不同，各自内部自洽但横向引用要小心）；DAC’25 的数据取自其原论文，属跨论文比较，条件可能不完全一致。

Q12：三个 headline 数字（17.6% / 24% / 21%）分别相对谁、怎么算的？

数字 指标（几何均值） EncyLogic 基线 出处
17.6% 布线后 ADP（ps·µm²） 22,564.13 BOiLS 27,390.25 Table 1
24% 工艺映射后时延（ps，ASAP7 FF） 133.69 &deepsyn 176.63（ratio 0.76） Table 2
21% FPGA LUT 数 257.00 &deepsyn 324.96（ratio 0.79） Table 2

补充几个次级数字：布线后时延几何均值 237.28 ps，比 BOiLS 的 258.42 好 8.2%；对 DAC’25 的 152.93 好 12.6%；FPGA 逻辑级数 9.00 → 7.77（-14%）。

为什么全程用几何均值？因为这个 benchmark 套件的 ADP 跨度从 10³ 到 3.5×10⁶（ctrl 只有 976，square 高达 351 万），算术均值会被大设计完全绑架，几何均值才反映”典型提升”。

Q13：哪里赢得漂亮？哪里输得难看？

赢面（论文重点宣传的案例）：

  • router：布线后时延 265.36 → 120.97 ps，ADP 提升 **73.1%**——拥塞敏感的设计上，”物理感知先验”的价值被放大到极致；
  • sin：面积 614 → 364 µm²，ADP 提升 32.6%——避免了激进序列常见的逻辑膨胀；
  • i2c（27.5%）、ctrl（24.8%）、arbiter（FPGA 上 LUT 2722 → 165、级数 18 → 6；ASIC 映射时延 347.26 → 85.33 ps）、int2float（71.06 → 50.01 ps）。

败笔（几何均值赢了，但单点翻车）：

  • adder：ADP 反而恶化 **-128.8%**（时延 686.77 vs BOiLS 的 310.53 ps；虽然仍远好于 &deepsyn 的 4237.40）。值得注意的是消融表中 adder 去掉 MCTS 后时延崩到 4013.96 ps——说明这个设计上 MCTS 的在线适配其实救回了很多，但仍没追上 BOiLS；
  • voter：ADP 恶化 -26.2%——时延其实更好（866.62 vs 997.82 ps），但面积 754 vs 519 µm² 惨败。这是单目标 reward 的直接代价：为时延牺牲面积；
  • max：工艺映射时延 996.04 ps，落后于 &deepsyn（815.44）和 DAC’25（612.07），FPGA 级数也更高（51 vs 41）。

怎么解读？个人解读：单目标（时延）优化的结构性副作用在 voter/max/adder 上显形；且对结构极简的设计（adder 类），搜索的统计优势摊薄。论文自己在 4.5 节承认单目标会带来面积波动，但主张 ADP 整体仍严格占优。

Q14：消融实验说明了什么？为什么 RLVR 和 MCTS 都”不可或缺”？

Table 3（14 个 benchmark，几何均值时延）：

配置 布线后时延 相对退化
完整 EncyLogic 284.46 ps —
去掉 MCTS（静态贪心解码） 356.11 ps +25.2%
去掉 RLVR（纯监督模仿） 372.74 ps +31.0%

两条结论各自对应一个”必须”：

  • RLVR 必须有：纯模仿学习只能复刻蒸馏数据的形，学不出对真实布线代价的对齐——去掉它，模型退化为”结构性模仿器”，时延几何均值直接恶化三成。RL 微调是把先验接到物理现实的那根线；
  • MCTS 必须有：通用先验不可能预知每个新设计的独特拓扑约束——静态贪心推理丢掉 25.2%。在线搜索负责把”平均意义上的好分布”裁剪成”这个设计合身的序列”。

一句话：RLVR 管分布对不对，MCTS 管这件衣服合不合身，两者正交、缺一不可。

Part 4 · 批判性视角：一篇细读之后该追问的事

Q15：一万条训练数据、六层 Transformer，真的能学出”分布”吗？

先别急着说小。这个”语言”比自然语言简单好几个数量级：词表 32、序列 25 步、语法结构高度局部——6 层 512 维对这个量级并不寒酸（类比：AlphaGo 的策略网络也就十几个卷积层）。消融结果也证明”小模型 + 强搜索”的组合已经足够打赢所有基线。

真正的风险不在参数量，在覆盖面（个人解读）：训练分布来自 OpenABC-D / ISCAS-85 的小规模电路，对真实工业规模设计（上万倍大）的分布偏移才是要害；论文的 benchmark 最大的 sin/square 也仍是学术规模。这属于”论文成立”与”工业可用”之间的经典缝隙。

Q16：训练序列只有 25 步，Fig.1 却说 500 步的天使序列还在涨——矛盾吗？

不矛盾，但值得追问。三层事实：

  1. Fig.1 是动机实验：随机 500 步长序列证明天使序列存在、且长 horizon 仍有优化空间；
  2. 训练语料是 25 步序列；
  3. 部署时 SeqTree 的外层迭代不断在基序列后追加（每轮至多 d 步、共 n 轮），最终序列可以远长于 25 步。

所以”长 horizon 能力”由在线搜索外推，先验只负责每一步的局部引导。真正开放的问题是：25 步学到的先验在数百步之后是否仍然可靠？ 论文没有直接检验这一点（个人解读：这是一个隐含假设，也是后续工作最自然的切入点之一）。

Q17：每次 MCTS 迭代平均 1064 秒——太贵了吧？

账要这么算：几何均值 1064.41 s/迭代（Table 1 Runtime 列，sin 单次约 4300 s），乘以迭代数 n，再加 GRPO 离线微调的布线成本。确实不便宜。论文的辩护分三层：

  1. NRE 语境：先进节点上，综合探索的一次性算力成本，远小于流片后才发现时序违例/布线拥塞的代价——这笔钱花在前面是”买保险”；
  2. 复杂度被先验钉死：GRPO 微调后的 SeqFormer 提供准确物理先验，高效剪枝 MCTS 树，避免状态空间爆炸；
  3. 基线也没便宜到哪去：BOiLS 这类黑盒优化本身就要反复跑物理评估（不过论文表格未列基线运行时，严格的时间公平性需要查全文/开源代码——这是个该追问的点）。

论文自己给出的解药：未来引入轻量、物理感知的代理模型加速评估、同时保住物理保真度。这个方向和 LLM 圈”verifier 蒸馏”的思路遥相呼应（个人解读）。

Q18：只优化时延，面积和功耗怎么办？

论文在 4.5 节正面回应：框架reward-agnostic，把 r_i 从 −D_i 换成多目标耦合形式（例如 r_i = −D_i − λ·Area_i）无需改动任何算法骨架。当前单目标设计是有意为之——用时延这个”前后端断连最严重的指标”来验证方法论。

但 voter 和 adder 的翻车已经演示了单目标的偏科：ADP 指标只能部分兜底，不是真正的帕累托前沿。自然的后续：多目标 reward、面积作硬约束的受控优化、或者奖励整形（reward shaping）下的三目标 PPA 协同。

Q19：细读表格，我发现了几个值得求证的小问题

以下是”审稿人视角”的观察，不影响主结论，但复现时应该问：

  1. cavlc 的数字打架：Table 1 中 Ency 时延 199.92 ps、面积 51 µm²、ADP 10,195.92（51×199.92 自洽）；Table 3 中 Ency 时延却是 160.49 ps、ADP 61,468——61,468/160.49 ≈ 383 µm²，与 51 对不上。同一方法同一基准出现两组互斥数字，疑为笔误或配置差异；
  2. “unseen”的程度无法核验：训练语料取自 OpenABC-D/ISCAS-85 的 33 个 AIG，而测试基准名（adder、arbiter、sin、voter……）恰好也是 OpenABC-D 的设计名。论文声明训练/测试完全分离，但正文未列出 33 个训练 AIG 的清单，读者无法确认”未见”的是设计本身还是其变体；
  3. AlphaSyn 缺席结果表：作为动机部分反复对比的在线 MCTS 基线，在 Table 1/2 中没有结果列（至少在正文表格范围内未见）；
  4. 关键超参未公开：d（搜索深度）、b（并行宽度）、M（轮数）、n（外层迭代数）、G（GRPO 组大小）、β（KL 系数）在正文中均以符号出现、未见取值；
  5. Table 1 与 Table 2 的 corner 不同（Best-Case vs FF），各自内部一致，但横向引用数字时要留心。

这类细节正是”论文说的 17.6%”与”你复现出的 17.6%”之间常见的缝隙所在。

Q20：这篇论文对”生成式 AI × EDA”这个大方向意味着什么？

五条启示（个人解读为主）：

  1. LLM 后训练配方可以整体平移进 EDA：蒸馏数据 → SFT → 可验证奖励的 GRPO → 测试时搜索。这套”SFT + RLVR + test-time search”的组合拳在逻辑综合上被完整验证。EDA 天然适合 RLVR：真值可算（跑工具就是了），只是贵——贵的部分用”批级验证 + 单调接受”控制；
  2. 代理-真值鸿沟是普遍病症：任何存在”廉价代理 + 昂贵真值”结构的领域（编译器 flag 优化、数据库查询计划、芯片布局布线、AutoML 管道），”学真值分布 + 批量真值验证 + 单调接受”都是可复用的模板；
  3. 小模型 + 强搜索 ≠ 落后：在 32 词表、25 步序列的窄域语言上，6 层 Transformer 就够，剩下交给测试时计算。这对”EDA 要不要上大模型”的争论提供了一个数据点：也许该上的是分布 + 搜索，而不是参数量；
  4. 开源 EDA 生态是被低估的功臣：ABC/Yosys/OpenROAD/OpenSTA + OpenABC-D 让”物理在环”的训练在学术实验室里变得可负担——没有这套栈，本文的方法论根本无法验证；
  5. 待办清单清晰可见：物理代理加速（论文自认）、多目标 reward、更大设计规模、更长 horizon 的先验外推、 encyclopedia 的持续扩充。
